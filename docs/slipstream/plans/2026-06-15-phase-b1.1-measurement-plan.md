> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox
> (`- [ ]`) syntax. Spec: `plans/2026-06-15-phase-b1-cooperative-gpu-design.md` §B1.1.

**Goal:** measure the Orchard-Sinsemilla-combine work's share of the **critical path** (net of
T6.9 write-behind overlap) in a real sync, on CLI + device — the go/stop gate + success bar for
the rest of B1. **Ships NO GPU into sync** (instruments the CPU `build_subtrees` path).

**Architecture:** the engine already emits a stage-split log (`engine.rs:233`) and `ScanStats`
already carries `persist_wait`/`persist_busy`. B1.1 adds one timed quantity — the wall time of
the **Orchard** `build_orchard_subtrees` call — threaded back through the same write-behind-lane
stat plumbing as `persist_busy`, surfaced in the stage-split log + a `--profile` JSON dump.

**Tech stack:** Rust (edition 2024, slipstream-core + slipstream-cli), `serde_json` for the
profile dump (already a transitive dep; confirm or add to cli only).

**Scope:** B1.1 ONLY. B1.2 (scheduler) and B1.3 (on-device ship) get their own plans **after**
B1.1's number is in hand — the measurement may change their design or say "stop." Writing them
now would be guessing.

**Conventions:** branch `slipstream`, LOCAL-ONLY (never push), commits
`[#1755] slipstream: B1.1 — <imperative>`, every commit = work + tests green + STATE.md.
Always-green = `cargo test -p slipstream-core -p slipstream-cli` + clippy both feature sets. No
`rust/`/root-Cargo.toml changes ⇒ no swift gate. No `unwrap`/`expect` outside tests; `tracing`

## ⚠️ EXECUTION DEVIATION (2026-06-15, recorded per executing-plans)

Reading the code before implementing surfaced two facts that reorder this plan:

1. **The Orchard combine wall is ALREADY measured + logged per chunk** — `orch_split.build_ms`
   (`persist.rs:941`, the "sparse orchard tree split" info log) wraps exactly the
   `build_orchard_subtrees` call. `persist_wait`/`persist_busy` already ride `ScanStats` + the
   stage-split log. So the go/stop number can be computed from EXISTING instrumentation (incl.
   the current device build) by summing per-chunk `build_ms` and comparing to `persist_wait_s`.
2. **The inline path is trait-bound:** `SparseFacade::put_blocks` is the `WalletWrite::put_blocks`
   trait method (`persist.rs:1202`) → must return `()`. The combine sub-stat therefore cannot
   flow back via return value; it needs a shared side-channel accumulator reachable across the
   write-behind **lane thread** (Tasks B1.1.1–B1.1.3) — non-trivial, touches the load-bearing
   persist path.

**Revised order (measurement-first):** do **B1.1.4 / B1.1.5 (MEASURE from existing logs) FIRST** —
no code. Sum per-chunk `build_ms`, compare to `persist_wait_s`/`persist_overlap_s` from a
**write-behind-ON** run, on the contended device (iPad A10) where the critical-path question is
live (the M4 likely shows `persist_wait≈0` = hidden regardless). **Only if that says "go"** do we
build the structured `SyncProfile` (Tasks B1.1.1–B1.1.3 below) for clean, repeatable, per-device
numbers. If "stop" (combines already hidden behind scan), we skip all the plumbing and close B1
honestly. Tasks B1.1.1–B1.1.3 are retained below as the "if go" build.

- [ ] **Step 3: Add the fields to `ScanStats`** (`scan.rs`, after `persist_busy`):

```rust

    /// Sinsemilla-combine work the GPU can address). Measured inside the persist
    /// path; with write-behind it is a component of `persist_busy`.

    /// B1.1: number of Orchard commitments (tree leaves) processed — combines ≈ leaves.
```

- [ ] **Step 4: Time the build + accumulate.** At the `build_orchard_subtrees` call in
  `persist.rs sparse_put_blocks`, wrap with `Instant::now()`, accumulate the elapsed and the

  `persist_busy`/`total_busy` is accumulated on the `PersistLane`), and surface both on
  `ScanStats` in the same drain site where `stats.persist_busy = wb.lane.total_busy()` is set
  (`scan.rs` write-behind barrier + the inline non-write-behind path):

```rust
// persist.rs, around the Orchard build site:
let _t = std::time::Instant::now();
let orchard_subtrees = build_orchard_subtrees(gpu_on, orch_start, &mut orchard_commitments);
// accumulate into the lane's stat sink (same channel as persist_busy):
sink.add_orchard_subtree(_t.elapsed(), orchard_commitments.len() as u64);
```

(Exact accumulator wiring follows the `total_busy` pattern; if `build_orchard_subtrees` runs on
the write-behind lane, the sink is the lane's; on the inline path, it's the local stats.)
